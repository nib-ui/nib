## 1. Goal & positioning

- Q1 Ambition: personal → niche community → Bootstrap-class, over time. Near-term target: one complete 1.0.
- Q2 Primary positioning: developer-facing products (docs, dashboards, CLI/tool landings, technical blogs). Shop/portfolio recipes stay as "it can do this too" examples.
- Q8 Domain customisation = **presets** (token bundle + recipe): default theme, density, mapping of the 3 free hues, built-in tags, sample pages. Presets never touch the laws.
- Q17 Core licence MIT. Later revenue: paid templates + premium presets; components are never paywalled.

## 3. Colour & design system

- Q5 Two tiers: fixed laws (radius 0, no shadows, mono/sans pairing, 1px/2px strokes, motion); open tokens (accent, 3 free hues, font families as long as the mono + sans pair stays, density).
- Q7/Q29 Accent **F: jade rule + ink inversion**. Dark `#00967d` / text `#009e84`; light `#02806c` / text `#007561`. Also: rule "ink inversion = selection/cursor only, never a button"; retune `syntax-keyword` / `syntax-number` (collide with teal); CVD test inside `theme check`. Both light and dark themes.
- Q27/Q32/Q33 Own icon set: 16/20 grid, 1px/2px strokes, square caps, 90°/45° angles only, `currentColor`, ~60–80 icons; SVG sprite + ESM + CSS mask. Icons accompany words by default; icon-only only for dense controls inside components, with mandatory `aria-label` + tooltip.
- Q16 Uppercase via `text-transform`; raise label line-height for Vietnamese diacritics; `:lang()` disables uppercase for CJK.
- T1 Default theme follows `prefers-color-scheme`; override with `data-theme` on `<html>` or any region; `light-dark()` + `color-scheme`; presets may set their own default.
- Note: JetBrains Mono has no `tnum` (no-op, not needed); Inter numerals need `tnum`.

## 4. Architecture

- Q4 CSS tokens first + optional scripts (reference: Appwrite Pink).
- Q9/Q18 1.0 = foundation + ~25 components + data grid, date picker, advanced combobox, command palette, framework wrappers. **Single release at 1.0.**
- Q19 Hand-written, **zero runtime dependencies**.
- Q30 Headless TS core (controllers: state, APG keyboard, ARIA); `js` / `react` / `vue` / `svelte` are thin bindings.
- Q31 1.0 wrappers: React, Vue, Svelte.
- Q10 Prefer the newest native HTML/CSS; ESM scripts with `init(root)` / `destroy()`, auto-init via `data-*`, idempotent (SPA-safe).
- Q34 Data grid: sort, row selection, sticky header, column resize, APG grid keyboard, pagination, simple cell edit, virtualisation from ~1k rows (no grouping / pivot / column drag / range selection). Date picker: single date, range, min/max, disabled dates, `Intl` (test vi-VN / en-US / ja-JP), no time / lunar calendar.
- Q45 Hand-written positioning module (placement → flip → shift → fit) for every floating element; removed once anchor positioning ships in all 3 engines.
- Q11 Prefixed component classes; state styled via ARIA (`aria-current` = accent); accessibility is a first-class concern.
- Q12 Source tokens in DTCG JSON → CSS vars, Tailwind v4 `@theme`, JSON (Figma later). Plain CSS, `@layer`, Lightning CSS, no Sass. DESIGN.md = spec/docs, not a build source.
- Q16/Q21 Prefixed utility system generated from tokens, opt-in file; layout / spacing / typography / colour roles / container only; no radius / shadow / gradient / blur; no class names that collide with Tailwind.
- Q20/Q37 Modern CSS used directly, no fallbacks. `@property` only for typed/animated properties, `inherits: true` by default.
- Q39 Two entries: plain (`@layer xx.theme, xx.base, xx.components, xx.utilities;` at the top of every file) and `xx/tailwind.css` (tokens in `:root` + `@theme inline` aliases, radius/shadow namespace reset, components in Tailwind's `components` layer; no reset, no utilities).
- Q41 `!important` banned (except reduced-motion, with an inline comment explaining why).
- T3 Structural RTL: logical properties only (lint blocks left/right), directional glyphs flip via `:dir(rtl)`.

## Follow-ups found while writing the spec (2026-10-24)

- **Resolved (ADR 9):** primary button = 2px ink border, transparent ground; hierarchy primary 2px → outline 1px → ghost; ink inversion means _chosen_ and never makes an action stand out (pressed toggles and selected options may use it); destructive confirm = 2px red border; no filled-button exception for landing CTAs.
- Syntax colors retuned off teal: keyword `#a98fc0` / `#6e4f8a` (mauve), number `#c2a26f` / `#7d5f2c` (ochre); ≥ 4.5:1 on surface raised in both themes.
- Label line-heights raised for Vietnamese diacritics: `label-md` 12/18, `label-sm` 11/16.
- Vocabulary settled with GLOSSARY.md (2026-10-24): in a listbox / combobox / command palette the option under the keyboard is _current_ (2px accent rule) and the selected value is the cursor block; the "highlighted" row state is renamed **flagged**; the `primary` color token is removed (the primary button's frame uses `on-surface`); surface "panel" is renamed **overlay** (`surface-overlay`); "side panel" is now **side column**.
- After the token-check prototype and Mobbin research (2026-10-24, ADR 10): primary button sits in the region's action row and never shares a row with a cursor block; cursor block only for single selection, multi-select = `[x]` + hover fill + bulk action bar; flagged rows always carry a word; type-to-confirm for permanent deletion of named resources; forms get an error summary, `OPTIONAL` marker (no asterisks), switch-vs-checkbox rule; knob-less `ON`/`OFF` switch kept (ON weight 500 on-surface, OFF on-surface 3, row hit area ≥ 44px); listbox current = accent rule + hover fill; disabled dates struck through; `COPY` → `COPIED ✓`; "On this page" current heading has a rule; `SKIP TO CONTENT` link. - Light hues retuned for tags (2026-10-24): `color-engine` gained the rule "hue text on its own `-soft` fill over all three surfaces ≥ 4.5:1"; the light green, blue, cyan and magenta failed it (4.16–4.41:1 on raised/overlay). Side effect: accent-vs-green CVD warnings drop from three to two (light protan gone; deutan 9.1, tritan 8.8). Dark hues, light red and yellow unchanged.
- Visual regression platform (2026-10-24, ADR 7 amendment): baselines made and compared in the Playwright Docker image on linux/arm64, locally (`pnpm update-snapshots`) and in CI (`ubuntu-24.04-arm` + container). Chosen over amd64 because QEMU amd64 emulation on Apple silicon made Chromium return NaN contrast to axe; x86 contributors rely on CI diffs. Size budgets now live in `size-budgets.json` at the root (gzip), read by each package's `.size-limit.js` and re-exported by `@nib-ui/test-harness`.
- `@nib-ui/dom` adapters (2026-10-24, #20): `runIntents()` runs intents in order and returns those whose element is missing (a binding that runs them before commit sees it); focus uses no `preventScroll`. `announce()` keeps one polite (`role=status`) and one assertive (`role=alert`) region per document, visually hidden through CSSOM (allowed by a strict `style-src`), empties then writes after 100 ms on core's `Clock` so a repeated message is spoken again, and a newer message cancels a pending one; while a modal `<dialog>` is open the region moves inside the topmost one (everything else is inert). `toNibEvent()` reads events by shape, not `instanceof`, so iframe events work; it treats `keyCode 229` as composing (Safari's IME keydown). `domGeometry().watch` is batched to one call per animation frame. Size budgets are now measured with `@size-limit/esbuild` (entry bundled with dependencies, minified, gzipped), because `@size-limit/file` only measured the entry file and missed re-exported modules.
- Binding bridges (2026-10-24, #21): attributes render by one rule in every binding (`domAttrs`: `undefined` is absent, anything else is its string, so `false` is `"false"`). Intents run after the framework commits: React queues them and forces a commit, then drains in a layout effect; Vue uses `nextTick`; Svelte `tick()`; vanilla runs them right after its synchronous DOM update. React applies changed options during render (shallow compare, so rebuilt options never loop), destroys the instance a microtask after unmount unless strict mode or `<Activity>` mounts it again, and recreates it if it was destroyed while hidden; `create` must be side-effect free until subscribed. Vue bumps a version after each option update so option-only changes re-render. The Svelte store creates its instance on the first subscriber and destroys it after the last. Ids: React and Vue use `useId`; Svelte asks for `$props.id()` (only allowed at a component's top level); vanilla uses the root's own `id`, else `uniqueId()`. `locale` defaults to the document `lang` on the client only, so server renders pass it explicitly. The Svelte bridge is a plain-TS store, so the package needs no Svelte compiler; its tests compile a fixture component with the Vite plugin, render it on Node to a file snapshot, and hydrate that snapshot in Chromium. Browser-safe test helpers live in `@nib-ui/test-harness/browser`.
- Docs skeleton (2026-10-24, #23): `apps/docs` is a static Astro 7 site importing `@nib-ui/css/nib.css` from the workspace build. `@nib-ui/css` is built with lightningcss (bundle + minify, bare imports resolved like Node); the build writes the layer-order statement back by hand because minifying drops it. The component page template (`component-page.astro`) has kicker, title, lead, a live example region, HTML / React / Vue / Svelte code tabs and a required Accessibility section. The `[T]DARK` / `[T]LIGHT` toggle (accessible name "Switch to dark theme") stores the choice in `localStorage` and an inline head script applies it before paint; CSS picks the word, so it is right without JS; with no choice the page follows the OS. Its printed hotkey is Alt+T, not a bare T: a single-character shortcut fails WCAG 2.1.4 (speech input, screen reader browse keys). Pages declare the layer order in an inline `<style>` before any stylesheet, because bundlers drop a bare layer statement. Site strings go through `src/i18n/ui.ts`; Astro's i18n config holds `en` only. E2E runs against the built site through a tiny Node static server, because `astro preview` detaches when not on a terminal; `astro check` uses its own `tsconfig.astro.json` so the references `nx sync` adds stay out of it. Vercel settings live in `apps/docs/vercel.json` (Root Directory `apps/docs`).
- Component generator (2026-10-24, #22): `nx g nib:component <name> --kind=css|interactive` lives in `tools/nx-plugin` (package `@nib-ui/nx-plugin`); the root devDependency `"nib": "workspace:@nib-ui/nx-plugin@*"` aliases it so Nx resolves the `nib:` collection (Nx finds local plugins by package name, not project name). File layout it fixes: `packages/css/src/components/<name>.css` (imported last in `nib.css`, also built standalone to `dist/components/`), `apps/docs/src/pages/components/<name>.astro`, `apps/docs/e2e/components/<name>.e2e.ts` (axe + screenshot of the Example region per matrix cell) and `<name>.keyboard.e2e.ts`; core `src/<name>/{<name>,index,<name>.apg,<name>.spec}.ts` exported as `@nib-ui/core/<name>`; bindings `src/<name>.ts` exported as `@nib-ui/<binding>/<name>` (`useX` for React and Vue, `createXStore()` for Svelte because names such as `switch` are reserved words, a self-registering `define()` module for vanilla, listed in `sideEffects`). Size budgets are derived from the package exports and component files, so the generator never edits them. Budgets are per package: a binding entry is measured without core, dom and its framework (each budgeted where it lives); core controllers are measured with the kernel; combobox, command palette, date picker and data grid get the heavy budget.
- Button (2026-10-24, #24): the first component, made with the generator. Fixed 28px (36px `lg`; on `pointer: coarse` 44px minimum, the primary 48px); density does not change it. Hover fill skips disabled and pressed buttons, so a disabled toggle keeps its block. The docs example prints `[ESC]CANCEL`: a platform glyph such as `[⌘↵]` must be written per platform with its `aria-keyshortcuts`. Every kind keeps a 1px border (transparent for ghost) and the primary's 2px frame gives the pixel back in padding, so all kinds line up. The action row is a component class, `nib-action-row` (flex, inline-end). The printed shortcut is `direction: ltr; unicode-bidi: isolate` so right-to-left text does not mirror `[⌘↵]`. In forced colours every button shows a `ButtonBorder` (the ghost's transparent border is overridden by the browser), pressed is `Highlight` / `HighlightText`, disabled `GrayText`. CSS budgets are checked by `scripts/css-size.ts` (gzip of the built files), because size-limit with the esbuild plugin reported 128 B for an 807 B stylesheet. The docs code panel, not the `<pre>`, scrolls, so keyboard users can reach overflowing code (axe `scrollable-region-focusable` at 360px).
- Listbox slice (2026-10-24, #25): choosing never follows the arrows (Enter, Space or click choose); on focus the chosen option, else the first enabled one, becomes current; the pointer moves current without scrolling; removing an item drops it from current only: the chosen value and checked rows stay while their item is missing (async loading, filtering) and no change is reported, so controlled callers never get `onValueChange` during render. `multiple` uses `aria-checked` + `data-checked` and `[x]` / `[ ]`, never `aria-selected`. `keys` maps actions (next, prev, first, last, choose) to key lists or `false`. Element ids follow `<id>-<part>[-<key>]`, which lets one APG table run in core and, through `apps/docs/e2e/apg.ts`, against every binding on fixture pages (`/test/<component>/<binding>/?case=n`, React/Vue/Svelte islands via Astro integrations). The conformance runner now fires `focus` on the target first when it has a handler, as a browser does. In forced colours a transparent border is painted, so the listbox's inline-start rule is `Canvas` except on the current option. Friction fixed on the way: the generator now also exports `@nib-ui/core/<name>/apg` (size budgets skip it); it does not run `nx sync`, so CONTRIBUTING says to run it; Svelte stores are `createXStore`; VR baselines must come from `pnpm update-snapshots`.
- Listbox review (2026-10-24, #25): Space continues a typeahead search that is still running (APG, native `<select>`), otherwise it chooses; a typed Space is `preventDefault`ed. AltGr (Ctrl+Alt on Windows) types characters but triggers no action. `choose` from the keyboard resolves the current option when the event is reduced, not from the rendered closure. The vanilla binding watches its options (MutationObserver on children, `data-disabled`, `data-nib-option`), reads `data-checked` as `defaultChecked`, and dispatches `nib:change` in a microtask so listeners see the updated DOM; `bind()` gained `refresh()` for markup that changes with no state change. A chosen option that is also disabled keeps block text (the disabled rule sits before the chosen one). Not changed, with reasons: `pointermove` stays (Chromium's post-scroll hover update fires boundary events, not moves, so `pointerover` would be the risky choice); repeated-letter cycling ("aa" → next "a…") is the APG trade-off; `aria-checked` without `aria-selected` in multiple mode is kept per the glossary and goes to the manual screen-reader pass (#63).
- Base (2026-10-24, #27): `@nib-ui/css` gains `src/base/{reset,typography,prose,layout}.css` in `nib.base`, imported before components. Type roles are classes `nib-text-<role>` (hero, xl, display, lead, heading, reading, body, small, label, micro, code, item, meta) plus `nib-kicker` and `nib-num`; `h1`–`h3` default to xl / display / heading at zero specificity. Caps come from `--nib-caps` and `--nib-caps-spacing` (button uses them too): `:lang()` turns them off for scripts without case and for cursive or abugida scripts where tracking breaks joining (Arabic, Hebrew, Indic, CJK, Thai, Lao, Khmer, Myanmar, Ethiopic…), and any `[lang]` turns them back on for an embedded cased language. Labels in docs are now written in sentence case (`Skip to content`, `Language`).
